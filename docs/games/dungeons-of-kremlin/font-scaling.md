# Масштабирование шрифтов / Font scaling

Патч `font-scaling` масштабирует родной игровой шрифт относительно 320×200.
Общий путь отрисовки используется меню, игровыми надписями и цифрами
[`numeric-hud`](numeric-hud.md). Патч выбирается отдельно, зависимостей нет.
Работает с RUS PKR.EXE и ENG PKE.EXE; оригиналы пользователя не изменялись.

## Образцы и причина

Исследование 20 октября 2026 года. Образцы и происхождение —
[versions.md](versions.md). SHA-256 оригиналов:

| Версия | Размер | SHA-256 |
|---|---:|---|
| RUS | 324824 | `12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28` |
| ENG | 340616 | `cce7bc5993d0734ad87e93db37a70b8b52faedfff14ac48d6e317e5ac996a37b` |

Методы: существующие листинг и декомпиляция Ghidra RUS, разбор NE,
Capstone в режиме x86/16, исполнение собственной вставки в Unicorn
и скрытые тестовые сессии DOSBox Staging 0.83 с цветными кадрами поверхности.
Оригинальные EXE читались только для анализа. Полные кадры, исполняемые копии
и отчёты находятся в игнорируемом `mqa/font-scaling-20261020/`.

Подтверждено: запуск выбирает ресурс FONT8 либо FONT16 по масштабу экрана.
Загрузчик берёт размер ресурса / 256 как высоту и устанавливает ту же ширину
символа. Рисование глифа всё равно перебирает восемь бит каждой исходной
строки и вызывает пиксельный метод один раз на бит. Это не масштабирует
растр пропорционально разрешению; фиксированные метрики дополнительно
влияют на интервал и центрирование. Простого изменения размеров метрик
для исправления недостаточно.

## Реализация

Все адреса таблицы — **индекс NE-сегмента:смещение внутри сегмента**,
не файловые смещения и не runtime-селекторы DPMI.

| Участок | RUS | ENG |
|---|---|---|
| Рисование одного глифа | `12:0158` | `4:153E` |
| Установка метрик после чтения шрифта | `12:0083` | `4:1431` |
| Аргумент выбора FONT16 | `2:0BED` | `2:0FD9` |
| Штатный форматированный вывод | `12:0338` | `4:171E` |
| FONT8 в сегменте данных | `51:0281` | `27:0263` |

Ветка FONT16 теперь тоже выбирает родной FONT8. Ресурсы игры не меняются.
Загрузчик после чтения данных устанавливает метрики по текущим dword-полям
ширины/высоты поверхности `+30h/+34h`: ширина `max(1, W//40)`,
высота `max(1, H//25)`. Оба измерения масштабируются независимо, сохраняя
относительный размер исходных 8×8 в экранной геометрии 320×200.

| Разрешение | Ячейка символа |
|---|---|
| 320×200 | 8×8 |
| 640×400 | 16×16 |
| 640×480 | 16×19 |
| 800×600 | 20×24 |
| 1024×768 | 25×30 |

Новая функция использует ближайший исходный пиксель: `sx=dx*8//width`,
`sy=dy*8//height`. Сохраняются исходные цвета переднего/заднего плана,
режим прозрачности, включительные границы clip-прямоугольника и знаковые
32-битные координаты. Оригинальные функции строк, printf, переноса строки
и расчёта расположения продолжают использовать поля `+22h/+24h`.
Числовой HUD центрирует цифры уже по новым метрикам.

Три правки имеют длину 340, 30 и 2 байта. Вспомогательная установка метрик
размещена в хвосте собственной функции глифа, вызывается near-call из
загрузчика. Размер EXE и таблицы релокаций сохраняются. Новых релокаций нет.
Проверяются уникальные контексты printf, загрузчика, строкового вывода,
ветки выбора шрифта и имён ресурсов; точные исходные/новые байты всех трёх
участков, обязательные цели loader-вызовов и все цепочки NE-fixup'ов.
Неоднозначность, смешанное состояние, запись загрузчика поверх вставки,
циклы, выходы за диапазон и far-входы внутрь заменённых участков отклоняются.

|---|---|
| RUS | `de086763e0550c146c6ac72d10cb650388486bcf6b0511128f5ec3cecf11b837` |
| ENG | `3a6b0b80f6de99a22712a67f35aa40713bc52dc9ceaeb56c03b6a2141d3debd6` |

## Сборка и проверки

Собственный код WASDify под MIT, NASM 2.16.03, `BITS 16`, плоский бинарный
вывод для существующего NE-кода. Far-cdecl вход глифа сохраняет BP, SI, DI,
DS и стек. DS устанавливается в SS; AX/BX/CX/DX/ES и флаги рабочие.
Near-помощник использует BP и аргумент поверхности из исходного загрузчика.
Runtime-селекторы, адрес загрузки сегмента и новые поля объекта не зашиваются.
NASM и Unicorn не нужны пользователю приложения.

```powershell
py scripts/build_kremlin_font_scaling.py --nasm build/tools/nasm-2.16.03/nasm.exe
# nasm -f bin -DENG=0/1 src/wasdify/patches/kremlin_font_scaling.asm -o ...
$env:PYTHONPATH='src;build/research-deps'
py scripts/verify_kremlin_font_scaling.py
py -m unittest discover -v
```

Для обоих языков NASM выдаёт одинаковые 340 байт функции:
SHA-256 `040cefc5225c74d98f38cf22d02301c8eb22883fcc6953a15d060eaf4b596e87`.
Различаются контексты, смещения и относительный вызов из загрузчика.
Сборщик требует побайтового совпадения с ресурсом пакета.

Unicorn: по 240 сценариев на язык, пять разрешений, шесть кодов символов,
включая 128/255, оба режима фона, отрицательные координаты, обрезка с четырёх
сторон и внутренний clip-прямоугольник. Пиксели сравниваются с независимым
расчётом; проверяются метрики, сохранение регистров и баланс стека при
разрушении рабочих регистров перехватываемым штатным пиксельным методом.

94 теста проходят на Python 3.14 и 3.11; семь GUI-тестов пропущены только
на embedded Python 3.11 без Tkinter. Тесты используют синтетические NE,
проверяют обе версии, сдвиг сегментов, повреждения, неоднозначность,
частичное применение, релокации, бэкапы и независимость от патча разрешения.
На реальных образцах без записи оригиналов проверены все пять патчей вместе,
последовательное применение в прямом/обратном порядке и повторное применение.

DOSBox: десять сессий RUS/ENG × пять разрешений со всеми пятью патчами.
Проверены активные метрики поверхности, переход в игру, смена чисел HUD
`73/42 → 9/0 → 100/100 → 1/1` и цветные кадры результата.
Текст пролога захвачен во всех десяти сессиях; меню выбора подземелья
визуально проверено в 320×200 и 1024×768 обеих языковых версий.
Полное прохождение, все игровые сообщения и сохранения отдельно не проверены.
Округление до целой ячейки даёт небольшую погрешность относительного размера
при дробном масштабе; длинные тексты сохраняют штатные ограничения размещения.

Wheel установлен и проверен вне репозитория: загружаются все пять патчей,
оба перевода и ресурс вставки. Игровых файлов в wheel нет.
Обновлённые `dist/WASDify.exe` и `dist/wasdify-cli.exe` собраны;
проверки каталога RU/EN и загрузки оконной точки входа прошли.

## Применение

В GUI выберите «Масштабирование шрифтов». Для CLI:

```powershell
wasdify plan C:\Games\Kremlin\PKR.EXE --patch font-scaling
wasdify apply C:\Games\Kremlin\PKR.EXE --patch font-scaling
```

Для ENG укажите PKE.EXE. Игра должна быть закрыта; бэкап включён по умолчанию.
Уже установленный numeric-hud переустанавливать не требуется. Для отката
восстановите сохранённый EXE из бэкапа при закрытой игре.
