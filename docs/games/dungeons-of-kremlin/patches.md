# Патчи

`save-load` устанавливается через общий Service для уровней 1–3 RUS/ENG.
[Совместимость, установка и границы проверки](save-load-integration.md).
Итоговые автоматические проверки и ручная приёмка ещё не завершены.

| ID | Назначение | Зависимости | Конфликты | Статус |
|---|---|---|---|---|
| `save-load` | Автономные сохранения по уровням, F5/F9, выбор продолжения | `weapon-selection-fix` | Нет среди реализованных патчей | Устанавливается для RUS/ENG 1–3; итоговая и ручная приёмка впереди |
| `weapon-selection-fix` | Безопасная проверка текущего оружия и сохранение курсора очереди событий при переключении | Нет | Нет | Реализован, RUS/ENG; [анализ и проверки](weapons.md) |
| `wasd` | WASD и прямой поворот мышью | Нет | Нет | Реализован, RUS/ENG; пользователь подтвердил работу в игре |
| `resolution-640x400` | `-r1`: 640×400 вместо 640×480 | Нет | Нет | Реализован, RUS/ENG; игровая проверка ожидается |
| `render-optimization` | Оптимизация горизонтального текстурирования | Нет | Нет | Необязательный, реализован для RUS/ENG; [замеры диагностических копий RUS](benchmark.md) |
| `numeric-hud` | Жизнь и заряд числами, два поля с родными значками | Нет | Нет | Реализован для RUS/ENG; [анализ и проверки](numeric-hud.md) |
| `font-scaling` | Масштабирование шрифтов меню, надписей и числового HUD | Нет | Нет | Реализован для RUS/ENG; [анализ и проверки](font-scaling.md) |
| `game-settings` | INI: разрешение, чувствительность, клавиши; отдельные RU/EN DOS setup | `wasd`, `resolution-640x400` | Нет | Реализован для RUS/ENG; [анализ и проверки DOSBox](settings.md); MS-DOS отдельно не проверена |

Рендер: [реализация, проверка и ограничения](render.md).
Для быстродействия в DOSBox Staging 0.83 рекомендуется сначала настроить
`core=dynamic` и `cpu_cycles_protected=max` в секции `[cpu]` и перезапустить
эмулятор. Эта настройка решила проблему пользователя. Дальнейшие оптимизации
рендера сняты с активного плана; готовый патч сохраняется.

## Исправление 640×400

Описание WASD, обновления чувствительности и рабочих копий: [wasd.md](wasd.md).

Меняет один байт `01 → 00` в `push 0101h`, получая `push 0100h`.
`-r2`, `-r3`, `-r4` и автоматическая ветка `-r` не изменяются.
Детали и сигнатуры — в [analysis.md](analysis.md). ASM-вставки не нужны.

Подтверждены образцы `rus-pkr` и `eng-pke`. Неизвестный хэш допускается только
при уникальной контекстной сигнатуре в корректном 16-битном NE-коде.
Ручной выбор игры, имя EXE и известный хэш не обходят проверку контекста.

| Образец | SHA-256 после патча |
|---|---|
| RUS PKR.EXE, 324824 байта | `f0b7e53d960569834b6798c120c702f0276f3527893b2afaa44b4c3e0c74a460` |
| ENG PKE.EXE, 340616 байт | `13b544dd17262c2aa662884854d77b5ea6d79dabf26a21d5271c20fa910dfc04` |

Проверка и применение к **рабочей копии**, при закрытой игре:

```powershell
wasdify plan "C:\Games\Kremlin\PKR.EXE" --patch resolution-640x400
wasdify apply "C:\Games\Kremlin\PKR.EXE" --patch resolution-640x400
```

Для ENG укажите `PKE.EXE`. В GUI выберите EXE, отметьте «Исправление разрешения
640×400», нажмите «Проверить», затем «Применить». В JSON-плане (`--json`)
ожидается одна правка: `expected=01`, `replacement=00`.
Саму игру запускайте в DOS/DOSBox: `PKR.EXE -r1` / `PKE.EXE -r1`.

Бэкап включён по умолчанию: `<EXE>.wasdify-<uuid>.bak` рядом с целью.
Откат: закройте игру и скопируйте сохранённый бэкап поверх EXE.
Повторное применение распознаётся по сигнатуре, без записи и нового бэкапа.
Service повторно проверяет исходный хэш и план перед атомарной заменой.
Оригиналы в `originals/` не изменялись. Не направляйте `apply` на эталон;
используйте рабочую копию. Новых зависимостей времени выполнения нет.

Исходная проверка разрешения включала 63 синтетических теста и 40 сценариев
Unicorn; отдельная визуальная проверка этого патча ещё не выполнена.
Текущий общий набор содержит 82 теста, включая WASD, оптимизацию рендера и стенд профилирования.

## Остальные патчи

Все три патча независимы, роль — `main`. Несовместимый контекст любого патча
блокирует **весь** набор: частичного применения нет.
Изменение игровых механик не является целью WASDify.

## Дополнительные файлы game-settings

`game-settings` устанавливает свой `SETUP.EXE` рядом с EXE игры из `WASDify.pak`.
Вариант RU/EN выбирается по содержимому EXE, отдельного выбора языка или папки нет.
Бэкапы и откат охватывают весь набор. Повторное применение восстанавливает setup,
если он отсутствует или отличается. [Поставка, установка и проверки](settings.md).

## Сохранение и загрузка: разработка

`save-load` пока не доступен для установки. Реализованы эталонный кодек KRS
и синтетические проверки, проведено дополнительное исследование Ghidra RUS/ENG.
Есть адаптеры очереди, дверей, полей мира и исследовательский DOS-транспорт.
Автономный игровой сериализатор проверен для уровней 1–3 RUS/ENG:
F5/F9, оба выбора после смерти, новый процесс и отдельные файлы каждого уровня.
Запуски — `mqa/save-native-levels-ru/start.cmd` и
`mqa/save-native-levels-en/start.cmd`. [Результаты шага 3](save-load-levels.md).
Ниже описан также прежний внешний прототип.
Для первого уровня RUS проверены мир, динамические снаряды, убитый враг, двери,
очередь и HUD после перезапуска через внешний Python-прототип с F5/F9.
Локальный запуск — `mqa/save-play-ru/start.cmd`; это ещё не автономный патч.
F9 также работает многократно в текущем процессе. При входе и после смерти есть
выбор «Начать уровень с начала» / «Загрузить сохранение», если запись доступна.
Без записи новое окно не появляется, обработка смерти остаётся ванильной.
Ранний опыт отдельно проверял двери и очередь после перезапуска
процесса; полного игрового сохранения этот стенд не создаёт.
[Текущий результат и оставшаяся работа](save-load-implementation.md).
