# Шаг 4: отказы и восстановление

23 октября 2026 года. Автономный KRN1, уровни 1–3 RUS/ENG.
Исходные EXE: RUS `12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28`,
ENG `cce7bc5993d0734ad87e93db37a70b8b52faedfff14ac48d6e317e5ac996a37b`.
Образцы, CRC ресурсов и результаты дизассемблирования/декомпиляции Ghidra
сохранены в [описании шага 3](save-load-levels.md). Здесь проверялся собственный
ASM и его исполнение; игровые ABI и оригинальные файлы не менялись.

## Исправления

| Найденный отказ | Решение |
|---|---|
| У SAV правильная CRC, но недопустимое здоровье/ссылки/состояние. Раньше он блокировал исправный PRV. | После привязки мира каждый кандидат проходит полную семантическую проверку до разрушения мира. Локальная граница `native_try_validate` позволяет отклонить кандидат и проверить следующий. |
| Повреждённый SAV блокировал последующие F5. | После полной проверки нового TMP удаляется только повреждённый SAV; PRV сохраняется. Ошибка доступа не трактуется как повреждение. |
| При ошибке установки первой записи проверенный TMP мог удаляться, хотя других записей ещё не было. | После успешного повторного чтения TMP становится записью восстановления и не удаляется обработчиком ошибки ротации. |
| После прерывания первой записи единственным файлом мог быть TMP, который загрузчик игнорировал. | Приоритет чтения SAV → PRV → TMP. Каждый кандидат проверяется; загрузка из резерва обозначается отдельной надписью. Чтение не переименовывает и не изменяет файлы. |
| Оставшийся TMP блокировал F5 без понятного действия. | Отдельное сообщение предлагает перенести TMP из папки игры. Автоматического удаления, перезаписи или миграции нет. |
| После ошибки close следующая операция могла оставить незакрытый дескриптор. | Одна дополнительная попытка закрытия. Исходная операция всё равно возвращает отказ, даже если очистка удалась. |
| Ошибка после начала пересоздания сразу завершала процесс, сообщение исчезало. | Аварийный экран ждёт нового нажатия и отпускания Enter. Затем DOS-процесс завершается; возврата в кадр с указателями на частичный мир нет. |

Раннее меню ещё не располагает миром: оно проверяет заголовок, схему, ресурсы,
длину, EOF и CRC. Полная семантическая проверка и окончательный выбор кандидата
происходят на первом связанном кадре до уничтожения мира. При отсутствии
пригодной записи F9 возвращает отказ; игра и текущий герой остаются доступными.

Состояние аварии не откатывается в памяти. Принятая граница первой поставки:
до изменения мира — отказ с продолжением игры; после начала пересоздания —
остановка и явный выход с сохранением файлов. Отдельный снимок для отката живого
мира, второй банк KRS, BAD-архив, lock-файлы и новое меню восстановления не добавлялись.

Отпечаток схемы теперь зависит от скалярных layout и явной wire revision,
а не от текстов меню. Смена надписи не меняет идентичность сейва. Исследовательские
файлы с прежним отпечатком не мигрируются: сохранения ещё не опубликованы.

## Синтетические проверки

```powershell
$env:PYTHONPATH='src;scripts;build/settings-deps'
.venv/Scripts/python.exe scripts/verify_kremlin_save_failures_synthetic.py --matrix
.venv/Scripts/python.exe scripts/verify_kremlin_save_native_synthetic.py
.venv/Scripts/python.exe scripts/verify_kremlin_save_io_synthetic.py
.venv/Scripts/python.exe scripts/verify_kremlin_save_instances_synthetic.py
.venv/Scripts/python.exe -m unittest discover -v
```

`build/settings-deps` содержит локальный Unicorn; он не нужен игре или WASDify.
Стенды выполняют настоящий NASM-код на придуманных объектах и файлах.
Оригиналы, их фрагменты и полные дампы не используются как фикстуры.

Новый стенд: 343 проверки. Для RUS/1 перебраны все 38 DOS-вызовов ротации
и 28 вызовов первой записи: отказ каждого вызова и остановка процесса после
каждого вызова. После остановки новый экземпляр загрузчика получает только
оставшиеся файлы, без памяти прежнего процесса. Пройдены также короткие записи
каждого из пяти блоков в обоих сценариях, что моделирует полный диск.
Перебор проверяет как сохранность прежней записи, так и чтение единственного
полного TMP после прерывания первой записи.

Для остальных пяти сочетаний повторены повреждения, резервное чтение,
запись после повреждения SAV, отказы create/commit/close/delete/rename,
защита чужого TMP и аварийное ожидание. Глубокий перебор каждого вызова
проводился для RUS/1; утверждения о шести идентичных полных переборах нет.

Дополнительно проходят 348 прежних проверок автономного ASM, 59 транспортных
и 8 CRC-проверок на язык, 37 проверок native-команд. 177 unit-тестов проходят
без пропусков в основном окружении. На Python 3.11.9 результат успешен;
8 GUI-тестов пропущены только из-за отсутствия Tkinter в этом интерпретаторе.
Новый unit-тест проверяет независимость отпечатка от текстов и его изменение
при изменении layout.

## DOSBox: реальные файловые операции и аварийная остановка

```powershell
$env:PYTHONPATH='src;scripts'
.venv/Scripts/python.exe scripts/verify_kremlin_save_failures.py --matrix
.venv/Scripts/python.exe scripts/verify_kremlin_save_native.py --matrix
.venv/Scripts/python.exe scripts/verify_kremlin_save_native_offline.py
```

Новый стенд создаёт отдельную копию для каждого сочетания. Хост подаёт ввод,
наблюдает и устраивает отказы между операциями игры; сериализацию, чтение,
проверку и восстановление выполняет payload. Короткие записи и точные ошибки
commit/close/rename моделируются синтетическим стендом, а не выдаются за
физический полный диск в DOSBox.

В каждом сочетании проверены чужой TMP с надписью о переносе, реальный отказ

Тестовый флаг по данным `+438` вызывает отказ после настоящего native-пересоздания

## Границы гарантий

Проверено восстановление после ошибок DOS и остановки процесса между вызовами.
Не заявляются атомарность rename при отключении питания, исправность диска
или поддержка нескольких одновременно пишущих процессов в одном каталоге.
Оставшийся TMP требует переноса пользователем перед новой записью; это
сознательное сохранение потенциально единственного исправного файла.

Общий Service пока не устанавливает `save-load`. Совместимость со всем набором
патчей, окончательное размещение файлов и итоговый игровой прогон остаются
в шагах 5–6. Проверки ошибок не доказывают полного прохождения всех карт
и сами по себе не заменяют проверку цветов экрана перед поставкой.
