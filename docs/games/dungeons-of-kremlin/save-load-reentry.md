# Чёрный экран при повторном выборе уровня

23 октября 2026 года, исправление по результатам ручной проверки первого уровня.
После Esc или завершения уровня повторный выбор мог оставлять чёрный экран.
Ошибка относилась к автономному `save-load`, включая вариант без файла сохранения.
Первый запуск и перезапуск всего процесса её не выявляли.

## Образцы и анализ

Использованы неизменённые эталоны из [списка версий](versions.md):

- RUS `PKR.EXE`, SHA-256
  `12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28`;
- ENG `PKE.EXE`, SHA-256
  `cce7bc5993d0734ad87e93db37a70b8b52faedfff14ac48d6e317e5ac996a37b`.

Для RUS повторно выполнены дизассемблирование и декомпиляция Ghidra:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/analyze_kremlin_save.ps1 -Scope live
```

Полный локальный отчёт — `build/save-research/live-ru.txt`. Адреса ниже —
**сегмент:смещение Ghidra**, не файловые смещения:

- `1008:1357–1362`: основной цикл вызывает деструктор `1098:0000`
  с флагом `3`, затем возвращается к выбору через `1008:0C22`;
- `1098:0000`: удаляются объекты; флаг `1` освобождает сам мир
  через `10A8:00B7`. Глобальный указатель `266Ah` не обнуляется;
- `1098:009F`: новый мир записывает свой указатель в `266Ah` только
  при следующей инициализации, после раннего перехвата `1008:0545`;
- ранний вызов `1008:0C6D`, возврат `1008:0C70`, выполняется до создания мира.
  Ненулевой глобальный указатель здесь может принадлежать освобождённому миру.

Прежний `native_available` вызывал `native_read_file` для SAV/PRV/TMP.
Его `native_segments` выполнял `LGS BP,[SS:266Ah]` ещё до открытия файла.
Загрузка освобождённого protected-mode селектора могла вызвать исключение;
отсутствие SAV не предотвращало ошибку. ENG использует тот же путь payload
с адресами профиля и сдвигом глобальных данных на `B0h`.

До исправления отдельная RUS-копия с полным набором патчей воспроизвела отказ
после первого Esc и повторного выбора:
`mqa/save-reentry-20261023-211732-163824/`. Дампы и игровые файлы остаются
только в игнорируемом `mqa/`.

## Исправление и обновление

В `native_segments` gate `3` разрешает только собственный сегмент снимка.
Глобальный указатель мира не читается, `GS:BP` не связывается со старым миром.
При полном кадре и после смерти сохраняются прежние привязка мира,
семантическая проверка файла и пересоздание объектов. Глобальные переменные
оригинальной игры ради обхода ошибки не подменяются.

Прежний устанавливаемый payload сохранён в
`data/kremlin_save_native_legacy.json` как собственный артефакт WASDify.
Обновление разрешается только после полного воспроизведения старой установки,
проверки исходного хэша, контекстов и релокаций. Повреждённый payload отклоняется.
Установленные настройки и остальные улучшения сохраняются; резервная копия
EXE включена по умолчанию. Формат KRN1, отпечаток схемы, имена и содержимое
пользовательских сохранений не меняются.

Закройте игру и примените `save-load` ещё раз обновлённым `dist/WASDify.exe`.
Уже установленная проверенная зависимость `weapon-selection-fix` удовлетворяет
требованию без повторного выбора. При первой установке оба патча выбираются явно.

## Проверки

Собственный MIT-код, `BITS 16` / 386, NASM 2.16.03, protected mode,
far-cdecl и прежние NE-релокации. Новых внешних адресов и runtime-зависимостей нет.
Команды воспроизводимой сборки и контракт релокаций описаны в
[описании native-payload](save-load-native.md).

Синтетический стенд исполняет настоящий NASM-код и отслеживает чтение глобального
указателя с заведомо недействительным значением. Раннее чтение отсутствующего,
повреждённого и исправного сохранения не обращается к этому указателю, включая
CRC-проверку. Для уровней 1–3 RUS/ENG пройдены 366 проверок с общей папкой слотов.
Все 195 модульных тестов проходят, включая обновление прежнего payload с настройками
и без них, резервную копию, повторное применение и отказ при повреждении.

Стенд запускает Service или готовый Windows EXE на отдельной копии игры:

```powershell
$env:PYTHONPATH='src;scripts'
.venv/Scripts/python.exe scripts/verify_kremlin_save_reentry.py
.venv/Scripts/python.exe scripts/verify_kremlin_save_reentry.py --language en
.venv/Scripts/python.exe scripts/verify_kremlin_save_reentry.py --minimal
.venv/Scripts/python.exe scripts/verify_kremlin_save_reentry.py --installer dist/WASDify.exe
```

В одном процессе проверяется последовательность Esc без сохранения → Esc с началом
заново → Esc с загрузкой → завершение с началом заново. Меню и сохранения обрабатывает
сама игра. Для ускорения проверки завершения хост задаёт штатное состояние выхода:
отрицательное здоровье героя, как native-событие выхода `1000`; прохождение уровня целиком этот опыт
не проверяет. В ENG драйвер также закрывает штатный экран истории перед ранним
выбором. Игровые проверки относятся к первому уровню; уровни 2–3 покрывает
синтетическое исполнение общего payload.

RUS дополнительно прошёл `--completion-load`, включая установку готовым EXE:
`mqa/save-reentry-20261023-213338-992775/`. Полный набор через Service:
`mqa/save-reentry-20261023-212923-123832/`; минимальный набор:
`mqa/save-reentry-20261023-212858-665586/`.

**Открытое ограничение ENG:** расширенный сценарий `--completion-load` после
нескольких переходов завершается остановкой уже после успешного восстановления
снимка (`N_SEQUENCE=5`, `N_PENDING=2`, `N_ERROR=0`). Пример:
`mqa/save-reentry-20261023-213242-183320/`. Esc без сохранения, начало заново
и загрузка после Esc в этом же процессе проходят. Это не следует выдавать
за полную приёмку ENG после завершения уровня. Причина дополнительного отказа
не установлена; связь с ранним чтением освобождённого указателя не подтверждена.
Повторная проверка с началом заново после завершения также не дошла до окончания
вступления: `mqa/save-reentry-20261023-214051-234560/`. Поэтому успешная игровая
приёмка исправления относится к RUS; исправный полный переход ENG после
завершения пока не подтверждён. Обычные повторные входы после Esc в ENG проверены.

Windows-сборка проверяет CLI, локали и ресурсы. Wheel установлен вне репозитория:
на Python 3.11.9 и 3.14.6 проверены RUS/ENG, установка, обновление прежнего payload
и повторное применение. Архивы не содержат оригиналов и `mqa/`.
