# Сохранение и загрузка «Подземелий Кремля»

Редакция 0.1, 21 октября 2026 года. Статус: **проект, патч не реализован**.
Документ задаёт игровое поведение, архитектуру и предлагаемый контейнер сохранения.
Он опирается на статический анализ Ghidra; полный состав сериализуемых полей
классов ещё предстоит установить. Формат нельзя объявлять стабильным до этой проверки.
Автономный игровой сериализатор ещё не проверен и не реализован.

Дополнение 21 октября: [код контейнера и новое исследование RUS/ENG](save-load-implementation.md).
Реализованы кодек KRS, адаптеры событий и дверей, дисковый транспорт и стенды
DOSBox. Дополнение 22 октября: внешний Python-прототип первого уровня RUS
записывает логический снимок и восстанавливает его после нового запуска,
включая проверенный боевой сценарий и HUD. F5/F9 доступны через отдельный launcher.
Найденные пропуски первого уровня RUS и аудит RNG/сценариев описаны в
[разборе состояния](save-load-state-gaps.md). Остальные уровни и устанавливаемый
патч ещё не готовы.
Инструкция ручной проверки и точные ограничения приведены в начале дополнения.

## 1. Решение о слотах

**Одно сохранение на уровень, всего три фиксированных продолжения.** Произвольные
нумерованные слоты, имена сохранений и отдельный quicksave не нужны в первой версии.
Игрок выбирает уровень и внутри него использует «Сохранить» / «Загрузить».
Переход к другому уровню не затирает прерванную попытку предыдущего.

Отправная точка геймдизайна — заданное пользователем устройство игры: три
независимых и не особенно длинных уровня. Независимость означает, что не требуется
хранить несколько ветвей общей кампании. Короткая продолжительность уменьшает
пользу от архива промежуточных точек. Но один общий слот создаёт ненужный выбор:
потерять попытку на первом уровне или отказаться от сохранения на втором.

| Вариант | Польза | Цена | Решение |
|---|---|---|---|
| Один общий слот | Минимум интерфейса | Другой уровень вытесняет текущую попытку | Допустимый минимум, но не основной вариант |
| По одному на каждый уровень | Можно прервать любой из трёх уровней | Три фиксированных записи | Выбран |
| Несколько ручных слотов на уровень | Эксперименты, несколько игроков, архив | Выбор слотов, управление перезаписью, больше меню | Отложен до реального запроса |

Для каждого продолжения хранится также **одна предыдущая успешная запись**.
Это защита от неудачного сохранения и повреждения файла, а не ещё три основных
слота. Предыдущую запись можно выбрать явно в подменю загрузки.
У игры нет обязанности запрещать повторные загрузки ради сложности: цель
функции — позволить прервать игру и избежать повторения уже пройденного участка.

Сохраняться разрешено в живом игровом мире, в том числе во время боя. Проверка
«рядом нет врагов» не вводится: она требует дополнительной логики и может мешать
прервать игру. Техническая согласованность достигается остановкой на границе
игрового шага, а не ограничением игровых ситуаций.

В первой версии нет периодического автосохранения, сохранения при смерти или
выходе. Они могут затереть полезную точку и усложняют ожидания игрока. Смерть,
завершение уровня и начало новой попытки сами по себе сохранения не изменяют.
Первая ручная запись новой попытки заменяет текущее продолжение этого уровня,
а прежнее продолжение становится предыдущим. Загрузка не расходует сохранение.

## 2. Поведение и интерфейс

Предлагаемые клавиши по умолчанию: **F5 — сохранить, F9 — загрузить текущее
продолжение выбранного уровня**. Оба действия срабатывают один раз на нажатие.
В изученном игровом обработчике RUS этих назначений нет; до реализации нужно
проверить все меню, обе версии и переназначения в SETUP.

Если у выбранного уровня нет сохранённой записи, он сразу запускается с начала:
дополнительное меню «Начать уровень с начала» / «Загрузить сохранение» не показывается.
Это меню появляется только при наличии проверенной совместимой записи уровня
и содержит оба пункта. Повреждённая или несовместимая запись не считается
доступным продолжением; её обработка описана в разделе восстановления.
Вопрос появляется сразу после выбора уровня, до его заставки, номера попытки
и первого игрового кадра. «Начать уровень с начала» продолжает штатный запуск
с заставкой и номером попытки; загрузка пропускает их и продолжает сохранённую игру.
Тот же выбор появляется после смерти при наличии подходящего сохранения.
Без сохранения сохраняется ванильная обработка смерти. Начало новой попытки
не удаляет и не перезаписывает запись. В обоих окнах используются одинаковые
надписи, стрелки и Enter; по умолчанию выбрана загрузка.
Перезапуск после смерти снова показывает штатную надпись с номером попытки.
В паузе планируются «Сохранить», «Загрузить», «Предыдущее сохранение».
F9 не переключает уровень. Загрузить другой уровень можно через его пункт меню.
F9 в текущей игре выполняет загрузку напрямую. Выбор между началом уровня
и загрузкой предусмотрен при входе и после смерти.
Обычный F5 не требует подтверждения. Предыдущая запись уменьшает цену ошибки.

При отсутствии записи F9 выводит сообщение, не начинает новый уровень.
В меню, заставках, при смерти и переходе между состояниями мира F5 не пишет файл.
Одновременные запросы сохранить/загрузить отменяются с сообщением о недоступности;
за один игровой шаг выполняется максимум одна операция.

### Штатное окно сообщений

По предложению пользователя результат операции выводится **в то же окно,
куда игра пишет свои сообщения**. Отдельных окон успеха, значков, звуков и
новой панели статуса не добавляется.

| Машинный ключ | Русский текст | English |
|---|---|---|
| `save_success` | Игра сохранена | Game saved |
| `load_success` | Игра загружена | Game loaded |
| `save_unavailable` | Сейчас сохранить нельзя | Cannot save now |
| `load_unavailable` | Сейчас загрузить нельзя | Cannot load now |
| `save_missing` | Нет сохранённой игры | No saved game |
| `save_failed` | Не удалось сохранить игру | Could not save game |
| `load_failed` | Не удалось загрузить игру | Could not load game |
| `save_incompatible` | Сохранение несовместимо | Incompatible saved game |
| `save_corrupt` | Сохранение повреждено | Saved game is damaged |
| `save_previous_loaded` | Загружено предыдущее сохранение | Previous saved game loaded |

«Игра сохранена» появляется только после проверки записанного файла и его
установки в целевое имя. «Игра загружена» — после восстановления объектов,
ссылок, событий, HUD и завершения перехода в игровой режим. При восстановлении
предыдущей записи используется отдельная строка из таблицы, чтобы игрок понимал,
почему состояние старее ожидаемого. Подробные коды ошибок остаются английскими
машинными ключами, а не текстом в игровом окне.

Сообщение загрузки ставится после восстановления мира и принудительной
перерисовки HUD: восстановление не должно затереть его старым текстом.
Обе успешные строки получают штатное время показа. Ожидание диска не уменьшает
это время и игровые таймеры. Ошибка сохраняет прежнюю запись; обработанная ошибка
чтения до замены мира сохраняет текущую игру.

Для RUS подтверждён подходящий метод **NE 25:1278**, Ghidra `10C0:1278`.
Он принимает два far-указателя: на игровой интерфейс и на строку, копирует
38 символов в `interface+2Ch`, дополняет пробелами, ставит нуль в `+52h`
и добавляет флаги `22h` в `+10h`. Обе строки пользователя помещаются.
Нельзя вызывать его как обычную near-функцию или передавать строку в UTF-8:
нужны исходная кодировка игрового шрифта, правильный DS и контракт far-cdecl.
ENG-вход и кодировки нужно проверить отдельно. Не использовать `25:155D`:
это блокирующая надпись с ожиданием ввода, у неё другой контракт.

Все новые подписи меню, запросы и ошибки должны получить RU/EN-варианты.
Строки оболочки WASDify добавляются в оба locale-каталога; игровые строки —
в обе языковые таблицы нового payload. Язык оболочки не задаёт язык игры.

## 3. Образцы, метод и границы доказательств

| Образец | Размер, байт | SHA-256 |
|---|---:|---|
| RUS PKR.EXE | 324824 | `12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28` |
| ENG PKE.EXE | 340616 | `cce7bc5993d0734ad87e93db37a70b8b52faedfff14ac48d6e317e5ac996a37b` |

Хэши обоих файлов повторно проверены 21 октября. Новое исследование выполнялось
в **Ghidra 12.1.2**, язык `x86:LE:16:Protected Mode`, существующий проект
`originals/source/pkr-ghidra/PKR-performance`, программа `PKR.EXE`.
Проект открывался с `-readOnly -noanalysis`; оригинальные EXE не изменялись.
Использованы новый экспорт выбранных функций, ранее полученный полный листинг
и сопоставление инструкций с декомпиляцией. Сегментированный ассемблерный листинг
имеет приоритет над автоматически восстановленными типами и прототипами C.

**Новый детальный разбор относится к RUS.** Сведения ENG о вводе, RTL и оружии
из прежних исследований не подтверждают готовность механизма сохранений ENG.
Три независимых коротких уровня — исходное условие пользователя; Ghidra
дополнительно подтверждает три ветви выбора уровня, но не их длительность.
Отсутствие готовой сериализации не доказано исчерпывающим поиском всех функций:
в исследованном основном цикле её вызовы не установлены.

### Подтверждённые точки RUS

В столбце NE указан **индекс сегмента таблицы:смещение**. Ghidra назначила
первому сегменту `1000`, далее шаг `8`; это адреса её модели, не селекторы DPMI
и не файловые смещения. `DS` ниже означает штатный сегмент данных игры.

| Назначение | NE | Ghidra | Наблюдение |
|---|---|---|---|
| Главная функция | `2:0719` | `1008:0719` | Создание мира, игровой цикл, разбор результата, уничтожение мира |
| Выбор уровня | `2:02F7` | `1008:02F7` | Варианты 1–3 меняют цифру в именах набора ресурсов |
| Создание мира | `20:02A7` | `1098:02A7` | Выделение `074Ah` байт, затем вызов `20:004F` |
| Загрузка исходного мира | `20:004F` | `1098:004F` | Заголовок, таблица 256 far-ссылок, три массива карты |
| Подготовка карты и объектов | `20:0EF7` | `1098:0EF7` | Преобразование массивов, разбор клеток и объектов |
| Вставка события | `8:0108` | `1038:0108` | Связывание кольца и изменение счётчиков |
| Обработка событий | `8:0284` | `1038:0284` | Обход кольца, косвенные вызовы обработчиков |
| Шаг мира | `20:30C1` | `1098:30C1` | Обновление игрового состояния в основном цикле |
| Получение команды | `25:14C7` | `10C0:14C7` | Вызывает ввод, возвращает указатель на маску `interface+28h` |
| Ввод | `25:1639` | `10C0:1639` | Различает удержание и одиночные нажатия |
| Сообщение | `25:1278` | `10C0:1278` | Запись текста в штатное окно сообщений |
| Проверка состояния героя | `14:193E` | `1068:193E` | В частности, обрабатывает нулевую жизнь и поле `+D6h` |

В главной функции `CALLF 8:0284` находится в `2:0DAF`, вызов шага мира —
в `2:0E44`, вызов рендера `20:5435` — в `2:0E84`, опрос команды —
в `2:0F94`. Это опорные адреса исследования, **не готовые места установки JMP**.
Инструкции, длину вытеснения и релокации перехвата ещё нужно проверить.

Из загрузчика установлено:

- `DS:266Ah` содержит far-указатель на мир; главный цикл получает героя
  из `world+442h`.
- Таблица `world+30Eh` содержит 256 far-ссылок. В функции поиска свободной
  записи `20:017D` есть обход индексов `0…255`. Типы всех записей ещё не описаны.
- Три массива по `1104h` байта копируются в `DS:608Ah`, `DS:718Eh`, `DS:8292h`.
  Их нельзя принимать за готовый формат карты: `20:0EF7` затем меняет их,
  в том числе переставляет строки и интерпретирует содержимое клеток.
- У героя имеются far-ссылки на оружие `+AAh`, выбранный/ожидаемый индексы
  `+CEh/+D0h`. Жизнь/заряд и максимумы — `+5Eh/+60h/+62h/+64h`.
  Подтверждение: [оружие](weapons.md), [HUD](numeric-hud.md).
- Курсор очереди событий RUS хранится в `DS:03ECh`. Сохранение внутри
  обработчика события может застать временно несогласованные ссылки.

## 4. Механизм: сериализация мира на границе шага

Сохраняется логическое состояние текущего уровня. Не сохраняются процесс,
регистры CPU, стек, селекторы DPMI, адреса кучи, видеопамять и состояние DOSBox.
Загрузка должна работать после полного выхода из игры и нового запуска.

Новый обработчик ввода только ставит `pending_save` или `pending_load`.
Он не вызывает дисковые функции и не меняет мир. Отдельный диспетчер обслуживает
запрос в основном потоке, после полного разбора предыдущей команды, завершения
шага мира и очереди событий, перед следующим шагом симуляции.
Кандидат — обратное ребро к `2:0D6A`; он требует проверки всех входящих ветвей.
Одного возврата из `8:0284` недостаточно: после него цикл ещё меняет мир.

На время операции мир заморожен. IRQ клавиатуры/таймера продолжает штатную
минимальную работу; нельзя держать прерывания выключенными во время файлового I/O.
Заявки блокируются от повторного входа, ввод обрабатывается по фронту нажатия.
После операции очищаются команды, накопленное смещение мыши и флаги нажатия;
нажатая F5/F9 должна быть отпущена перед новым запросом. Игровые часы
перебазируются, чтобы время чтения файла не стало большим шагом симуляции.

### Что входит в снимок

| Состояние | Представление | Восстановление |
|---|---|---|
| Уровень, правила, время попытки | Числовые ID и логические счётчики | До запуска симуляции |
| Герой | Положение, направление, движение, ресурсы, ключи, инвентарь, состояние оружия | Через адаптер класса и штатные setter'ы, где они безопасны |
| Все живые игровые объекты | Тип, ID, изменяемые поля, ссылки через ID | Создание без побочных эффектов, затем связывание |
| Удалённые/подобранные объекты | Полный состав существующих экземпляров и состояние карт | Не создавать заново удалённые экземпляры из исходной карты |
| Карта | Изменяемые слои, двери, переключатели, доступность, исследованность | Применить после исходной геометрии, затем перестроить производные индексы |
| События и анимации | Владелец, тип операции, порядок, стадия, оставшееся время | Без вызова событий в процессе связывания |
| Генератор случайных чисел и сценарии | Все влияющие на продолжение состояния | Восстановить перед первым игровым шагом |

Список — требования к исследованию и адаптерам, а не утверждение, что у каждого
названного свойства уже найдено поле. Двери, AI, снаряды, сценарии, RNG и
исследованность карты требуют отдельного подтверждения структуры.
Поле `player+D6h` также нельзя исключать, пока не установлен его контракт.

Все сохраняемые ссылки переводятся в `object_id`. Ноль означает отсутствие
ссылки; остальные ID — уникальные `u32` в пределах файла. Внутренние индексы
таблицы мира сохраняются отдельно и не уплотняются: они могут участвовать
в ссылках карты или скриптов. Динамическим объектам назначается явный ID.
Таблица из 256 элементов не считается доказательством, что всего объектов,
включая оружие, события и вложенные сущности, не бывает больше 256.

Для каждого класса нужен проверенный адаптер:
`capture`, `validate`, `construct_without_activation`, `bind`, `activate`.
Тип объекта/события выбирается из белого списка кода патча. Far-указатели,
адреса методов и таблиц виртуальных функций никогда не берутся из файла.
Ресурсы задаются проверенными ID. Неизвестный класс блокирует запись;
нельзя молча пропустить объект и показать «Игра сохранена».

### Порядок загрузки

1. Приостановить игру. Полностью проверить файл, совместимость, длины,
   CRC, ID, диапазоны полей, ресурсы, ссылки и предельные объёмы выделения.
   До этого текущий мир не уничтожать.
2. До изменения мира любой отказ оставляет игру доступной. Для первой поставки
   после начала пересоздания допустим только остановленный аварийный экран
   с выходом по новому Enter; частичный мир не продолжает симуляцию.
   Откат живой попытки в памяти не требуется. Запись на диске не изменяется загрузкой.
3. Подготовить исходные ресурсы нужного уровня. Использовать штатную загрузку
   ресурсов, но не запускать обычные стартовые события, звук, выдачу предметов
   или случайную генерацию. Изучить, как отделить эти действия от конструкторов.
4. Создать точный набор сохранённых объектов без активации. Применить поля
   и изменения карт; установить все ссылки во втором проходе. Восстановить
   инвентарь, оружие, владельцев и порядок событий, RNG и таймеры.
5. Пересоздать производные структуры, поверхности и HUD для текущего видеорежима.
   Проверить связи кольца и владение объектами. Только затем разрешить события.
6. Очистить ввод, перебазировать часы, обновить ссылки главного цикла на мир
   и героя, сбросить его временные флаги и локальные кэши. Поставить сообщение
   «Игра загружена», возобновить симуляцию со следующего полного шага.

Глобальные указатели недостаточны: основной цикл держит мир и героя в локальных
переменных. Возврат в старый кадр после замены объектов создаст висячие ссылки.
Перехват должен возвращаться через явную ветвь переинициализации контекста цикла.

При ошибке построения нового мира освободить частично созданные объекты и
восстановить снимок отката. Если откат также невозможен, безопасно выйти в меню
и сообщить об ошибке; продолжение с частично восстановленными объектами запрещено.
Не обещать атомарность изменения памяти при нехватке ресурсов. Двойной мир
одновременно не обязателен, но бюджет памяти отката нужно измерить на всех уровнях.

## 5. Исследовательский проект KRS, версия контейнера 1

После шага 4 выбран автономный KRN1, описанный в [save-load-native.md](save-load-native.md).
Ниже сохранён отдельный исследовательский проект контейнера и Python-кодека;
это не требование реализовать его секции и банки в первой поставке.
Совместимость с исследовательскими файлами и миграция не требуются.

Бинарный файл с little-endian числами и явными размерами. Без выравнивания,
сжатия, нативных структур компилятора и встроенных ресурсов игры.
Все смещения ниже — **файловые**. Заголовок занимает ровно `128` байт.

| Смещение | Размер | Поле | Контракт |
|---:|---:|---|---|
| `00h` | 8 | `magic` | ASCII `WASDKRS` и нулевой байт |
| `08h` | 2 | `container_version` | `1` |
| `0Ah` | 2 | `header_size` | `128` |
| `0Ch` | 4 | `file_size` | Точный размер всего файла |
| `10h` | 4 | `schema_id` | Ненулевой ID полного набора схем полей и событий |
| `14h` | 4 | `compat_id` | Ненулевой ID семантики игры и адаптера версии |
| `18h` | 1 | `level_id` | `1…3` |
| `19h` | 1 | `language_id` | `1` RUS, `2` ENG |
| `1Ah` | 2 | `flags` | `0` в версии 1 |
| `1Ch` | 8 | `generation` | `1…2^64−1`, монотонно в пределах уровня |
| `24h` | 8 | `play_ticks` | Прошедшее время попытки в единицах 1/100 секунды |
| `2Ch` | 32 | `content_sha256` | Отпечаток полного зависимого набора ресурсов уровня |
| `4Ch` | 32 | `source_sha256` | SHA-256 исходного EXE до патчей, для диагностики |
| `6Ch` | 4 | `chunk_count` | Число секций, `1…32` |
| `70h` | 4 | `body_crc32` | CRC всех байтов после заголовка |
| `74h` | 4 | `header_crc32` | CRC заголовка при нулевом этом поле |
| `78h` | 8 | `reserved` | Все байты нулевые |

`play_ticks` — только время попытки; исходные таймеры событий преобразуются
адаптером без потери их точности. Для них не навязывается единица 1/100 секунды.
Время изменения файла не участвует в выборе последней записи.

CRC-32: отражённый полином `EDB88320h`, начальное значение `FFFFFFFFh`,
финальный XOR `FFFFFFFFh`. Проверочный вектор ASCII `123456789` → `CBF43926h`.
CRC выявляет повреждения, но не заменяет семантическую проверку данных.

### Секции

За заголовком следуют секции без промежутков. Заголовок секции: `tag[4]` ASCII,
`version:u16`, `flags:u16`, `payload_size:u32`, `payload_crc32:u32`, затем payload.
Итого 16 байт перед payload. Бит 0 флагов означает обязательную секцию;
прочие биты нулевые. Неизвестная обязательная секция отклоняется, необязательная
может быть пропущена после проверки границ и CRC. В версии 1 все секции ниже
обязательны, имеют версию 1, встречаются ровно по разу и идут в указанном порядке.

| Tag | Состав |
|---|---|
| `GAME` | Поля состояния попытки и сценариев; ссылка на героя |
| `MAPS` | Изменяемые слои и состояние мира |
| `OBJS` | Все сохраняемые экземпляры, включая героя и оружие |
| `EVNT` | Активные события в порядке обработки |
| `RNGS` | Состояния всех используемых генераторов случайных чисел |

В конце нет дописанных данных: сумма заголовка и секций должна равняться
`file_size`. Верхний предел файла — **1 MiB**, объектов — `4096`, событий —
`16384`; это защитные проектные лимиты, а не измеренные максимумы игры.
Они должны быть подтверждены измерениями или пересмотрены до фиксации схемы.
Чтение и CRC выполняются блоками до 4096 байт, с явным учётом границ сегментов.
Файловый лимит не означает необходимость единого буфера такого размера.

### Записи и схемы полей

`OBJS`: `count:u32`, затем `count` записей:
`object_id:u32, class_id:u16, class_version:u16, native_index:u16,
reserved:u16=0, fields_size:u32, fields[fields_size]`.
`native_index=FFFFh` означает отсутствие записи в штатной индексной таблице;
`0…255` — исходный индекс. Уникальность индекса проверяется среди его владельцев.

`EVNT`: `count:u32`, затем записи:
`event_id:u32, owner_id:u32, event_type:u16, event_version:u16,
fields_size:u32, fields[fields_size]`.
Порядок записей задаёт порядок обхода, первая — следующий логический элемент
обработки. Индивидуальные параметры содержат оставшееся время, стадию и ссылки
через ID. Вызовы и абсолютные адреса таймеров не записываются.

`GAME`, `MAPS`, `RNGS` и `fields` используют общую последовательность полей:
`field_id:u16, wire_type:u8, reserved:u8=0, value_size:u32, value[value_size]`.
Поля идут по возрастанию ID, повторов нет. Типы: `1=u8`, `2=u16`, `3=u32`,
`4=s16`, `5=s32`, `6=u64`, `7=object_ref:u32`, `8=bytes`.
Числовая длина должна точно соответствовать типу. Каждый `bytes` имеет
определённую схемой структуру и предел, а не произвольный дамп памяти.

**До реализации требуется отдельный реестр схем**: ID, тип, обязательность,
допустимые значения каждого поля, единицы координат, форматы слоёв, классы,
события, представление RNG, таблицы ресурсов и правила их создания.
`schema_id` ссылается на этот полный реестр. Пустая секция RNG или пропущенные
поля не разрешены без доказательства, что соответствующего состояния нет.
Назначать ID по случайно встреченному адресу или сохранять непросмотренные
байты объекта запрещено. Эта редакция фиксирует проект контейнера и механизм,
но **не выдаёт неполную карту классов за готовую спецификацию сериализатора**.

### Совместимость

Требуется точное совпадение поддерживаемых `schema_id`, `compat_id`, языка,
уровня и `content_sha256`. В первой реализации перенос RUS ↔ ENG запрещён;
разрешить его можно после доказательства соответствия ресурсов и классов.
Хэш изменённого EXE не используется как единственный критерий: смена разрешения,
масштаба шрифта или клавиш не должна сама по себе портить сохранение.
Изменение семантики мира/оружия требует нового `compat_id` либо явной миграции.
Неизвестное сочетание отвергается, даже если ID игры и размер файла совпадают.

`content_sha256` вычисляется над отсортированным по байтам ASCII-ID списком
всех зависимых ресурсов: для каждого `id_length:u16`, `id`, `size:u32`,
`sha256[32]`. ID — внутренние нормализованные ключи, не локальные пути.
Список должен включать сценарии, таблицы объектов и зависимости уровня;
его точный состав фиксируется в реестре схем. Отпечатки можно вычислять
при входе на уровень и кэшировать в пределах неизменённого набора ресурсов.

## 6. Запись на DOS-диск и восстановление

Для каждого уровня RUS используются `KRN1/2/3.SAV`, для ENG — `KEN1/2/3.SAV`;
рядом находятся PRV и TMP с тем же префиксом. SAV имеет приоритет, затем PRV,
затем TMP. Каждая запись проверяется целиком до изменения мира. После загрузки
резервной записи выводится отдельное сообщение; откат к прежнему моменту
не должен быть молчаливым. Чтение не меняет файлы.

1. Захватить и проверить снимок в памяти; неизвестное состояние блокирует запись.
2. Создать TMP эксклюзивно. Существующий TMP не удалять и не перезаписывать:
   сообщить, что его нужно перенести из папки игры, чтобы разрешить запись.
   При отсутствии исправных SAV/PRV загрузчик может восстановить проверенный TMP.
3. Проверить каждый write, commit и close. Перечитать TMP, проверить размер, EOF,
   CRC и логическое состояние. До этой проверки ошибка удаляет только собственный
   незавершённый TMP. Проверенный TMP сохраняется при последующих отказах.
4. Если SAV исправен, удалить прежний PRV, переименовать SAV в PRV, затем TMP в SAV.
   Если SAV отсутствует, установить TMP, сохраняя PRV. Если SAV повреждён,
   удалить только повреждённый SAV после проверки TMP; PRV сохранить.
   Ошибка доступа к SAV не считается доказательством повреждения: запись отменяется.
5. Перечитать SAV и сравнить с проверенным снимком. Только затем сообщить об успехе.

При кратковременной ошибке close делается одна повторная попытка освобождения
дескриптора; сама операция всё равно считается неуспешной. Полный диск, запрет
записи, ошибка чтения, commit, close, удаления или rename не должны уничтожать
последнюю проверенную запись. Первое сохранение может ещё не иметь PRV.
Прерывание после записи TMP допускает его проверенное восстановление.

Формат не требует двух банков, номеров поколений, BAD-архива, меню миграции
или lock-файлов. Доступ к одному каталогу ограничен одним процессом игры;
совместная запись нескольких процессов в один слот не поддерживается.
Эксклюзивное создание TMP предотвращает одновременную запись одного TMP.
Системную защиту от параллельной загрузки или внешнего изменения файлов
это не обещает.

Это восстановление после ошибок DOS и остановки процесса, а не гарантия
атомарности файловой системы при отключении питания или повреждении диска.
Операции используют DPMI и conventional bounce buffer; protected-mode far-указатели
не передаются реальному DOS. Текущий автономный launcher монтирует каталог игры
как рабочий каталог; выбор пути при окончательной интеграции относится к шагу 5.

## 7. Встраивание в WASDify

Будущий ID патча — `save-load`. Пока не регистрировать реализацию, не менять
`implemented` и не предлагать пользователю демонстрационное применение.
Установщик изменяет EXE; сама DOS-игра создаёт сохранения во время работы.
Файлы пользователя и игровые ресурсы не входят в пакет WASDify.

Предлагаемая обязательная зависимость — `weapon-selection-fix`: продолжение
должно корректно переживать последующие переключения оружия и изменения очереди.
Это проектное требование, проверяемое при реализации. Пользователь выбирает
зависимость явно. `wasd`, разрешение, HUD и масштабирование шрифта не должны
быть обязательны. Поддержка `game-settings` требует согласования перехватов ввода
и добавления `save`/`load` в обе языковые версии SETUP, проверки конфликтов.
Не записывать новые биты команд поверх неизвестных штатных значений.

Ожидается собственный 16-битный кодовый сегмент и сегмент рабочих данных
с буферами/таблицами ID; число сегментов и бюджет памяти ещё не измерены.
Решение об их добавлении принимается после проверки места в NE-заголовке
и совместной установки с сегментами настроек. Нельзя считать их номера постоянными.
Нужны явные NE-релокации far/selector-ссылок, сохранение ABI и контроль стека.

CLI и GUI вызывают общий `Service`. Анализ всех выбранных патчей предшествует
записи; общий план проверяет пересечения, зависимости, циклы и релокации.
Каждая точка установки требует уникального контекста, ожидаемых инструкций
и анализа входящих переходов. Известный SHA-256 идентифицирует версию,
но не заменяет эти проверки. Повторная установка проверяется воспроизведением
состояния; один маркер payload не доказывает корректность.

Перед выпуском NASM-вставки документируются команда сборки, `BITS 16`, ABI,
предположения о сегментах/релокациях, происхождение и воспроизводимые байты.
NASM не нужен при запуске WASDify или игры. Резервная копия EXE включена
по умолчанию; пользовательские оригиналы не изменяются при исследовании.

## 8. Неустановленное и порядок реализации

Порядок уточнён 22 октября 2026 года: ближайший результат — полное продолжение
**первого уровня RUS после перезапуска процесса**. Исследование остальных уровней
и ENG не является предварительным условием этого прототипа. Пользовательский
патч по-прежнему требует полного покрытия заявленных версий и приёмки ниже.
До первого полного продолжения не расширять контейнер KRS, не добавлять миграции
и необязательные секции. Меню восстановления TMP/BAD и устаревших блокировок
перенести на последующий этап; на стенде допустим явный отказ без изменения
исправной записи. Пропуск неизвестного игрового состояния недопустим.

| Этап | Что получить | Условие перехода дальше |
|---|---|---|
| 1. Проверка компонентов через перезапуск | Двери и очередь RUS первого уровня, свежие привязки памяти | Отличающееся состояние восстановлено; штатная анимация продолжается. Не считать полным сохранением |
| 2. Состояние первого уровня RUS | Поля всех встречающихся классов, карты, ресурсы, RNG, сценарии и объёмы | Полный логический снимок без неизвестных полей |
| 3. Сквозной прототип RUS | Создание и освобождение объектов, связывание, переход в цикл, запись и чтение снимка | Закрыть игру → открыть → восстановить мир, включая убитого врага, предмет, дверь и оружие; продолжить симуляцию |
| 4. Расширение покрытия | Остальные уровни, ENG, лимиты памяти и отказоустойчивость | Тот же сценарий для всех заявленных вариантов и проверки ошибок |
| 5. Пользовательская функция | F5/F9, меню, сообщения, предыдущая запись и восстановление файлов | Готовое поведение разделов 1, 2 и 6 |
| 6. Интеграция | Контекстные сигнатуры, совместимость патчей, RU/EN, документация | Все проверки ниже и явный статус реализации |

Недостаточно сохранить героя и повторно загрузить исходную карту: это воскресит
врагов и предметы, сбросит двери и события. Недостаточно дампа DS или кучи:
после нового запуска far-ссылки и выделения будут другими. Сохранение только
в начале уровня также не решает задачу прервать текущую попытку.

## 9. Приёмка

Синтетические тесты не используют игровые EXE или полные дампы как фикстуры.
Проверяются заголовки, CRC, усечения во всех полях, переполнения сумм/счётчиков,
неизвестные версии, повторные ID, отсутствующие ссылки, классы и события,
семантически неверные координаты/индексы, лимиты и несовместимые ресурсы.
Циклические ссылки объектов могут быть законны; проверяются их типы и владение,
а у очереди — корректное замкнутое кольцо без посторонних узлов.

Обязательны сбои на каждом шаге записи/закрытия/повторного чтения/переименования,
полный диск, каталог без записи, старый TMP, повреждённый последний банк,
отказ выделения при загрузке и отказ отката. Последняя исправная дисковая запись
должна оставаться доступной. Нельзя показывать сообщение успеха при любом отказе.

На рабочих копиях RUS/ENG в DOSBox для **всех трёх уровней**:

- Сохранить после движения, поворота, урона, подбора ключа и расхода заряда.
  Выйти из процесса, загрузить после нового запуска; сравнить канонический
  снимок полей, карт и ссылок, исключив оформление и абсолютные часы.
- Проверить убитого врага, исчезнувший предмет, открытую дверь, переключатель,
  изменённую карту и состояние сценария. После загрузки они не сбрасываются.
- Проверить полёт снаряда, активный AI, анимацию и смену оружия в разных стадиях;
  затем многократно переключать оружие и продолжать бой без повреждения очереди.
- Повторить загрузку одной записи много раз, в том числе после смерти,
  из другого уровня через меню, с другой раскладкой памяти и другим видеорежимом.
- Сохранить уровни 1 и 2; продолжение обоих доступно. Перезапись уровня 2
  не меняет файлы уровня 1. Предыдущая запись действительно содержит прошлую точку.
- Выбрать уровень без сохранённой записи: он сразу начинается, меню
  «Начать уровень с начала» / «Загрузить сохранение» не появляется. После успешного сохранения
  повторный выбор этого уровня показывает оба пункта.
- Удержание F5/F9 не создаёт серию операций. Время I/O не наносит урон,
  не завершает таймеры и не вызывает скачок движения после возврата.
- «Игра сохранена» / «Игра загружена» появляются в штатном окне, читаются
  в 320×200 и высоких разрешениях, с исходным и числовым HUD, с масштабированием
  шрифта и без него. Проверить английские варианты и сообщение об откате к предыдущей записи.

Перед выпуском: `python -m unittest discover -v`; при изменении упаковки —
установка wheel и загрузка ресурсов вне репозитория. Полные игровые дампы,
копии EXE и отчёты динамического стенда остаются в игнорируемых `originals/`,
`mqa/` или `build/` и не публикуются.

## 10. Воспроизводимость исследования

Новые локальные экспорты: `build/save-research/functions-ru.txt`,
`build/save-research/loader-ru.txt`; журналы — рядом. Это полные листинги
исследованных функций, они не предназначены для Git. Скрипт
`scripts/GhidraKremlinWeapons.java`, несмотря на историческое имя, принимает
произвольный список адресов и экспортирует инструкции с декомпиляцией.

Пример повторения из корня репозитория; пути установки Ghidra/JDK задаются локально:

```powershell
$taskRoot = (Get-Location).Path
$taskGhidra = 'C:/Users/dspev/AppData/Local/Programs/Ghidra/ghidra_12.1.2_PUBLIC'
$taskJava = 'C:/Users/dspev/AppData/Local/Programs/Ghidra/java/jdk-21.0.12.1+1'
New-Item -ItemType Directory -Force build/save-research | Out-Null
$taskPreviousLocalAppData = $env:LOCALAPPDATA
try {
    $env:LOCALAPPDATA = "$taskRoot/build/ghidra-local"
    $taskArgs = @(
        '-Djava.system.class.loader=ghidra.GhidraClassLoader',
        "-Duser.home=$taskRoot/build/ghidra-home",
        "-Dapplication.settingsdir=$taskRoot/build/ghidra-settings",
        '-Djava.awt.headless=true', '-Xmx2G', '-cp',
        "$taskGhidra/Ghidra/Framework/Utility/lib/Utility.jar",
        'ghidra.Ghidra', 'ghidra.app.util.headless.AnalyzeHeadless',
        "$taskRoot/originals/source/pkr-ghidra", 'PKR-performance',
        '-process', 'PKR.EXE', '-readOnly', '-noanalysis',
        '-scriptPath', "$taskRoot/scripts", '-postScript',
        'GhidraKremlinWeapons.java',
        "$taskRoot/build/save-research/functions-ru.txt",
        '1008:0719,1008:02f7,1098:02a7,10c0:1639,1038:0284,1098:30c1,1068:193e'
    )
    & "$taskJava/bin/java.exe" @taskArgs
    if ($LASTEXITCODE -ne 0) { throw 'Ghidra export failed' }
    $taskArgs[-2] = "$taskRoot/build/save-research/loader-ru.txt"
    $taskArgs[-1] = '1098:004f,1098:0ef7,1038:0108,10c0:14c7,10c0:1278'
    & "$taskJava/bin/java.exe" @taskArgs
    if ($LASTEXITCODE -ne 0) { throw 'Ghidra export failed' }
} finally {
    $env:LOCALAPPDATA = $taskPreviousLocalAppData
}
```

Исследование не меняет код ядра, каталог патчей или исполняемые файлы игры.
Следующий результат разработки — полный реестр состояния и проверка обратного
восстановления; только после него можно фиксировать схему и реализовывать патч.
