# Сохранения: принятое состояние и оставшаяся работа

22 октября 2026 года. Пользователь подтвердил работу текущего прототипа после
переноса выбора перед заставкой и восстановления номера попытки.
Этот файл — текущий план; подробности и история опытов находятся в
[описании реализации](save-load-implementation.md), требования к итоговому патчу —
в [спецификации](save-load-spec.md).

## Принято и не требует повторной переделки

- F5 сохраняет, F9 загружает, в том числе повторно в текущем процессе.
- При наличии подходящего файла вопрос появляется сразу после выбора уровня,
  до заставки, создания мира и появления игрока.
- Начало с начала проходит штатное вступление. Загрузка его пропускает.
- После смерти доступны те же два варианта. Перезапуск показывает штатный номер
  попытки. Без сохранения дополнительного вопроса нет, действует ванильная игра.
- Сообщения о ходе и завершении операций написаны прописными буквами родным шрифтом.
- Скорость записи и загрузки принята пользователем. Самостоятельных нажатий Enter
  в игровом мосте нет. Начало новой попытки не перезаписывает сохранение.

Локальный запуск: `mqa/save-play-ru/start.cmd`. Оригиналы не меняются.
Прежний запуск использует внешний Python-мост через API DOSBox.
Шаг 2 перенёс первый уровень исходной RUS-версии в автономный 16-битный payload:
новый запуск — `mqa/save-native-ru/start.cmd`, без Python, HTTP и NASM во время игры.
Это ещё не устанавливаемый через WASDify патч.
`KRS1.PROTO` / `KRS1.PRV` остаются файлами прежнего прототипа; автономная копия
использует отдельные `KRN1.SAV` / `KRN1.PRV` и не изменяет старые сохранения.
[Реализация, сборка и проверки шага 2](save-load-native.md).

23 октября: шаг 3 расширил автономный payload на уровни 1–3 RUS и ENG.
Новые игровые запуски — `mqa/save-native-levels-ru/start.cmd` и
`mqa/save-native-levels-en/start.cmd`. Файлы разделены по уровню и языку:
`KRN1/2/3.SAV` для RUS, `KEN1/2/3.SAV` для ENG, каждый со своими PRV/TMP.
[ABI, анализ Ghidra, сборка и матрица проверок шага 3](save-load-levels.md).

Шаг 1 проверен отдельным стендом `scripts/verify_kremlin_save_gaps.py`:
продолжение эффекта поверхности, повторное занятие слота снарядом и активация
неиспользуемого определения AI переживают новый процесс и повторную загрузку.
Для контрпримера AI стенд задаёт только начальное размещение; активацию,
очередь и движение исполняет игра. Это контролируемый игровой опыт, а не
утверждение, что исходная карта сама размещает этого врага.
Методы первого уровня исследованы в Ghidra: в подтверждённых ветках AI,
снарядов, триггеров и анимаций нет отдельного PRNG/seed; продолжение определяется
картами, командами, счётчиками и относительными таймерами. Подробности и границы
этого вывода — в [разборе пропусков](save-load-state-gaps.md).

Предыдущая проверка принятого интерфейса: 173 unit-теста, 37 синтетических проверок native-команд,
по 59 проверок транспорта и 8 CRC для RUS/ENG. Игровые сценарии и надпись
«2 ПОПЫТКА» проверены в `mqa/save-entry-20261022-220314-581115/`,
повторные загрузки и варианты после смерти — в
`mqa/save-live-20261022-220352-519600/`.
Раннее меню и продолжение с цветной палитрой дополнительно проверены в настоящем
окне DOSBox. Равенство индексов пикселей само по себе не проверяет видимость экрана.

Счётчик попыток записывается в новых файлах. У старых файлов его точное историческое
значение отсутствует; они остаются читаемыми с описанным в реализации значением по умолчанию.

## Блокеры и границы сложности

Для принятого локального сценария пользователь больше не сообщил блокеров.
Зависимость сериализации уровней 1–3 RUS/ENG от внешнего моста снята.
Матрица игровых сценариев шага 3 проверена; совместимость с остальными патчами
и полное прохождение всех карт ещё не проверены.

Следующая конкретная задача — шаг 4: полный аудит отказов и восстановления
автономной реализации. Принятые меню сохранены; повторять переделку интерфейса
без нового дефекта не требуется.
Двухбанковый контейнер KRS и дополнительные механизмы восстановления следует
сверить с реальными отказами при аудите автономного payload; их наличие в проекте не
доказывает необходимости каждого механизма для первой поставки. Первый автономный
вариант использует проверенный временный файл и предыдущую запись; полный аудит
отказов и окончательный выбор производственного формата остаются в шаге 4.

`save-load` остаётся вне реестра реализованных патчей до готовности настоящей установки.
