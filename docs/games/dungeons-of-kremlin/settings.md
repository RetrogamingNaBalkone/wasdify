# Настройки игры и DOS SETUP.EXE

Реализовано 20 октября 2026 года для `rus-pkr` и `eng-pke` из
[versions.md](versions.md). Оригиналы не изменяются. Игра остаётся DOS-программой
со штатными RTM.EXE/DPMI16BI.OVL; setup — отдельный DOS MZ EXE для 386+/VGA.
Python, Windows и NASM не нужны в гостевой системе.

## Почему отдельный setup

Текстовый setup запускается независимо от графики игры и позволяет исправить
неподдерживаемое разрешение. Встроенное меню потребовало бы дополнительных
изменений оригинального интерфейса обеих версий, а разрешение всё равно
применяется при запуске. Цена выбранного решения — для изменения настроек
нужно выйти из игры.

**Русской игре соответствует русский SETUP.EXE, английской — английский.**
Это разные сборки одного собственного исходника. Русская сборка устанавливает
свои 32 растровых глифа кириллицы 8×16 через BIOS VGA; установленная кодовая
страница DOS не требуется. Шрифт и ASM-код WASDify — собственные, MIT.
Латинские обозначения физических клавиш не зависят от раскладки.

## Установка и использование

Явно выберите все три патча; зависимости автоматически не добавляются:

```powershell
wasdify plan C:\Games\Kremlin\RUS\PKR.EXE --patch wasd --patch resolution-640x400 --patch game-settings
wasdify apply C:\Games\Kremlin\RUS\PKR.EXE --patch wasd --patch resolution-640x400 --patch game-settings
wasdify setup C:\Games\Kremlin\RUS --setup-lang ru
wasdify setup C:\Games\Kremlin\ENG --setup-lang en
```

Для английской игры применяйте патчи к `PKE.EXE`. Язык `--setup-lang` задаётся
обязательно и не зависит от `--lang` интерфейса WASDify. В GUI есть отдельный
выбор языка DOS setup; после распознавания игры он заполняется по языку EXE.
Выгрузка setup и транзакция патча — разные операции. При существующем другом
SETUP.EXE CLI требует `--overwrite` и сохраняет проверенную резервную копию.
GUI существующий другой setup не заменяет.

В DOS запустите `SETUP.EXE` из нужной папки. Стрелки выбирают пункт и меняют
значение, Enter открывает редактирование, Esc возвращает назад или выходит.
На странице клавиш Left/Right выбирают один из двух слотов, Enter захватывает
физическую клавишу, Del очищает слот, Esc отменяет захват. Дубликаты между
слотами или действиями блокируют сохранение. Доступен сброс стандартных значений.

Setup сохраняет KREMLIN.INI рядом с собой. Разместите его рядом с EXE игры:
игра читает INI **сама**, setup не служит обязательным загрузчиком и не изменяет
игровой EXE. Обе программы определяют каталог своего EXE, не меняя текущий
каталог. Штатный поиск игровых ресурсов остаётся оригинальным: для обычной игры
по-прежнему запускайте EXE из папки с её ресурсами.

## Формат INI

ASCII, CRLF; имена секций/ключей нечувствительны к регистру. Поддерживаются
пробелы, табуляция и комментарии `;`/`#`. Максимум 4096 байт, 127 символов строки.
Слишком длинный файл игнорируется, слишком длинная строка пропускается.
Неизвестные секции и ключи игнорируются. Дубликаты известных полей обрабатываются
по порядку; последнее поле задаёт значение либо стандартное значение при ошибке.
Версия отсутствует/неподдерживаема — весь файл игнорируется.

```ini
[wasdify]
version=1
[video]
mode=0
[mouse]
sensitivity=5
[keys]
forward=17,72
backward=31,80
strafe_left=30,0
strafe_right=32,0
```

Неперечисленные назначения сохраняют стандартные значения. Значения клавиш —
десятичные физические скан-коды штатного обработчика; `0` означает пустой слот.
Расширенные клавиши и цифровая клавиатура имеют штатные общие коды (например,
Up/Num8); независимые E0-назначения не добавляются. PrintScreen/Pause со сложными
последовательностями, неподдерживаемые коды и числа вне диапазона отвергаются.
Неправильное назначение или любой конфликт сбрасывает **всю секцию клавиш**
к стандартной таблице, не затрагивая корректные видео/мышь.

### Разрешение и мышь

`mode=0` — штатный VGA 320×200; `-1` — автоматический выбор `-r`;
`1..4` — 640×400, 640×480, 800×600, 1024×768. Явный `-r…`/`/r…` (также
в верхнем регистре) имеет приоритет над INI. Приоритет далее: INI, штатные
значения игры. Ошибка числового режима даёт VGA. При недоступном явном режиме
из INI проверяется реальный результат VBE `4F02h`; текущий запуск использует
VGA, INI не переписывается. Автоматическая ветка остаётся штатной, включая
известную особенность проверки режима 0100h. CLI-режимы сохраняют исходное поведение.

Шкала мыши — `0..9`; стандартная новая конфигурация — **5 (0,15°)**.
Нынешние 0,2° соответствуют **7**. Формула градусов на единицу INT 33h:

```text
6 / (5 × (13 − sensitivity))
```

Относительная кривая и десять ступеней взяты из первичных исходников
[Wolfenstein 3D: меню](https://github.com/id-Software/wolf3d/blob/master/WOLFSRC/WL_MENU.C)
и [обработка мыши](https://github.com/id-Software/wolf3d/blob/master/WOLFSRC/WL_PLAY.C).
Код не переносился; абсолютные угловые значения откалиброваны для этой игры.
Ступень 0 не отключает мышь. Диапазон — примерно 0,092–0,3°.
Отсутствующий/неподдерживаемый INI сохраняет 0,2° прежнего WASD. Ошибочное
значение чувствительности в поддерживаемом файле даёт ступень 5.

Сохраняются прямой поворот, знаковая 32-битная арифметика, дробный остаток,
нормализация угла и проверка героя в существующей функции потребления мыши.
Стрелки и Shift не меняют чувствительность; кнопки мыши действуют штатно.

### Полная таблица игровых назначений

| Ключ INI | Стандартные клавиши | Обработка |
|---|---|---|
| `forward`, `backward` | W / Up, S / Down | Удержание |
| `strafe_left`, `strafe_right` | A, D | Удержание |
| `turn_left`, `turn_right` | Left, Right | Удержание, со штатным разгоном |
| `strafe_modifier` | Alt | Удержание; поворотные клавиши дают стрейф |
| `fire` | Ctrl | Удержание |
| `use` | Space / Enter | Штатное одиночное событие |
| `run` | Left Shift / Right Shift | Удержание |
| `map` | Tab | Переключение по одиночному событию |
| `zoom_in`, `zoom_out` | Num+, Num− | Штатное одиночное событие |
| `weapon_1`, `weapon_2`, `weapon_3` | 1, 2, 3 | Штатное удержание |
| `pause` | P | Штатная пауза по одиночному событию |
| `menu` | Esc | Штатное одиночное событие |
| `joystick` | J | Переключение штатного джойстика |

У штатного одиночного события состояние клавиши равно `2`; это не то же самое,
что бит удержания `1`. Используются исходные функции чтения/потребления события.
Навигация исходных меню не переназначается. Совместные направления и отмена
противоположных вкладов сохраняются существующим WASD-патчем.

**Старая D — отладочный вывод памяти, а не отдельная игровая команда.**
Функция ставит флаг `0122h` в поле `+10h`, а отрисовка при бите `0100h`
выбирает строку `ПАМЯТЬ: %ldMb %ldKb…`. В настройках эта ветка обходится;
её нет в назначениях и она не переносится на другую клавишу. D даёт только
стрейф. Отключённые WASD-патчем M/Y не возвращаются. У переключения джойстика
сохраняется функция, но старое всплывающее уведомление не выводится.

## Доказательства и устройство патча

Исследованы исходные SHA-256 из versions.md: RUS
`12f78afc0eba05f76b5dc0bb99da38d7daa20585024c0ba958fe828aa3864d28`, ENG
`cce7bc5993d0734ad87e93db37a70b8b52faedfff14ac48d6e317e5ac996a37b`.
Методы: Ghidra 12.1.2 в read-only/headless, таблицы NE и релокаций,
сопоставление малых контекстов, исполнение собственных вставок Unicorn 2.1.4,
изолированные DOSBox-прогоны рабочих копий. Полные экспорты не входят в пакет.

Адреса ниже — **смещения внутри исходных NE-сегментов**, не файловые адреса
и не селекторы, выделенные DOS-extender:

| Объект | RUS | ENG |
|---|---|---|
| Стартовая функция | сегмент 2, `0719h` | сегмент 2, `0AA9h` |
| Игровой ввод | сегмент 25, `1639h` | сегмент 11, `199Ch` |
| Удерживаемая клавиша | сегмент 15, `025Fh` | сегмент 6, `026Bh` |
| Одиночное событие | сегмент 15, `02ABh` | сегмент 6, `02B7h` |
| Отладочная команда D | сегмент 25, `1457h` | сегмент 11, `17BAh` |
| RTL open/read/close | сегмент 1, `498Ah` / `0AB2h` / `474Ah` | Те же смещения |

Стартовые локальные переменные различаются: селектор режима `[BP−1Ah]` RUS
и `[BP−58h]` ENG. Это учтено отдельными контекстами и сборками. Перехват
исполняет вытесненную инструкцию, сохраняет регистры/флаги и загружает INI
до штатного разбора командной строки и создания поверхностей.

Файловые вызовы используют штатные far-функции RTL с корректным игровым DS,
передавая защищённые far-указатели штатной DOS-среде исполнения. Прямые
DOS-вызовы setup работают только с его реальными сегментами. В игровом коде
единственный новый прямой BIOS-вызов — VBE без указателей.

Добавляются два NE-сегмента: собственный код и 12 KiB изменяемых данных.
Две записи таблицы занимают проверенное свободное место заголовка; следующие
таблицы сдвигаются на 16 байт, их NE-смещения и абсолютный указатель имён
пересчитываются. Индексы исходных сегментов и существующие файловые сегменты
сохраняются. Вставки используют новые внутренние far/selector fixup; расширение
трёх исходных таблиц релокаций допускается только в проверенные нулевые байты.

Весь выбранный набор сначала анализируется по исходному снимку. Общий
планировщик собирает результат в памяти и возвращает непересекающиеся правки
с владельцами-патчами. Проверка диапазонов, конфликтов и ожидаемых байтов
не отключается. Маркер установленного патча сам по себе не считается
доказательством: восстановление контекста и воспроизведение установки должны
дать побайтово тот же результат. Повреждённые/частичные состояния отклоняются.

## Сохранение и проверки

Setup эксклюзивно создаёт `KREMLIN.TMP`, проверяет полную запись, закрытие,
повторное чтение и байты. Прежний INI переименовывается в первое свободное имя
`KRE0000.BAK`…`KRE9999.BAK`; существующие бэкапы не перезаписываются. При отказе
замены выполняется возврат прежнего INI. Если возврат тоже не удался,
сохраняются восстановимые BAK и TMP. Это не гарантия атомарности при сбое питания.
Оставшийся TMP блокирует следующую запись: сначала проверьте его вручную.

Проверены 6946 сценариев исполнения инструкций: общие парсер/сериализатор обеих
языковых сборок, ошибки версии/значений/дубликатов/переполнений, загрузка RTL,
приоритет CLI, отсутствие INI, все ступени мыши и знаковые пределы, назначения,
короткая запись, ошибки чтения/закрытия/проверки, резервирования, замены и возврата;
IRQ-захват обычных/модификаторных/E0-клавиш, фильтрация Pause/PrintScreen,
сохранение регистров и подтверждение PIC. Все 106 unit-тестов проходят; Python
3.11 пропускает восемь GUI-тестов из-за отсутствия Tk в минимальном embedded
окружении, в основном окружении все восемь GUI-тестов проходят. Тесты используют
только синтетические NE-контейнеры и собственные DOS-байты.

Wheel установлен и проверен из рабочего каталога вне репозитория: каталог,
оба перевода, обе выгрузки setup и отсутствие импорта Tk при работе CLI.
Пересобранный автономный WASDify.exe прошёл проверку текущего каталога и
побайтовую проверку обеих DOS-сборок. Ресурсы берутся явно из текущего `src`,
даже если в окружении сборки установлена старая WASDify.

В DOSBox проверены RU/EN setup, создание INI, повторная запись с бэкапом,
запуск основного EXE без setup, все четыре VESA-разрешения и VGA, автоматический
режим, CLI поверх INI и VGA fallback при `machine=vgaonly`; отсутствие INI,
неподдерживаемая версия и файл сверх лимита; запуск без мышиного драйвера.
В игровом процессе
обеих версий подтверждены переназначение W→E, отсутствие реакции на старую W
и независимый стрейф D. Эти проверки ввода используют гостевую память для
воспроизведения состояния штатного IRQ, а не физические клавиши хоста.
Набор совместим со всеми существующими патчами; проверено их последующее
отдельное применение к EXE с настройками.

**MS-DOS на реальном оборудовании/в отдельной VM пока не проверена.**
Также остаются физический плейтест мыши/клавиш, длительная проходимость и
совместимость с иными VBE BIOS. DOSBox не заменяет эти проверки.

## Воспроизведение сборки

```powershell
python scripts/build_kremlin_settings.py --nasm build/tools/nasm-2.16.03/nasm.exe
python scripts/verify_kremlin_settings.py
python -m unittest discover -v
python scripts/verify_kremlin_settings_dosbox.py ru --setup
python scripts/verify_kremlin_settings_dosbox.py en --mode 1 --gameplay
```

NASM 2.16.03, `BITS 16`, `-f bin`; отдельные `ENG=0/1` и `LANG_RU=0/1`.
Сборщик создаёт таблицы из спецификации и двух locale-каталогов, вычисляет
real-mode положение данных setup, формирует MZ-заголовок и сравнивает все
байты с готовыми ресурсами. `--refresh` предназначен только для осознанного
обновления ресурсов при разработке. Runtime-сборка/загрузка исходников не нужна.
