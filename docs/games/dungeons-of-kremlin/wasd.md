# WASD и прямой поворот мышью

18 октября 2026 года. Патч реализован для PKR.EXE и PKE.EXE,
в публичном каталоге `implemented=true`. Пользователь подтвердил корректную
работу в игре и принял реализацию. Чувствительность оставлена на 0,2°;
плейтестинг на разных компьютерах и настройках DOSBox — дальнейшая работа,
не блокирующая готовность патча.

## Управление

Физические W/S — вперёд/назад, A/D — выделенный стрейф. Стрелки и их разгон
сохранены, Alt меняет только горизонтальные стрелки на стрейф. Мышь включается
автоматически, M не отключает её, Y не влияет на управление. Кнопки мыши
сохраняют штатные действия. Движение, стрейф и поворот работают совместно.

Чувствительность — **0,2° на единицу горизонтального счётчика INT 33h**:
`delta X * 2 / 10`, вдвое ниже предыдущих 0,4°. Вклад мыши добавляется к углу
напрямую, без клавиатурного разгона и ограничения углового шага. Вклады мыши
и стрелок складываются. Shift не меняет чувствительность мыши.

Игра хранит целые градусы; дробный остаток сохраняется между опросами, включая
нулевые кадры. Десять смещений +1 дают тот же результат, что одно +10.
Нулевые события не создают инерции. Вычисления знаковые 32-битные,
угол нормализуется по модулю 360 без переполнения signed word.

## Доказательства и сборка

Эталоны — `rus-pkr` и `eng-pke`; исходные SHA-256 в [versions.md](versions.md).
Ниже указаны **смещения внутри NE-сегментов**, не файловые адреса.

| Объект | RUS | ENG |
|---|---|---|
| Игровой ввод | сегмент 25, `1639h` | сегмент 11, `199Ch` |
| Мышь | сегмент 21, `0139h` | сегмент 8, `0139h` |
| Движение игрока | сегмент 14, `0A85h` | сегмент 5, `0F8Fh` |
| Чтение клавиши | сегмент 15, `025Fh` | сегмент 6, `026Bh` |
| Вызов добавления угла | сегмент 14, `0C3Dh` | сегмент 5, `1147h` |
| Функция добавления угла | сегмент 14, `0DB0h` | сегмент 5, `12BAh` |

Мышиная вставка `0174h..0202h` вычисляет целый и дробный вклад, затем
переходит к кнопкам `025Eh`, не выставляя виртуальные биты поворота 4/8.
Прежний накопитель X (`08A2h` RUS / `09B2h` ENG в DS) хранит ожидающие
градусы modulo 360; прежний накопитель Y хранит дробный числитель −9…9.
Near-call вместо `les bx,[bp+6]` забирает и обнуляет целый вклад, меняет угол
`[es:bx+32h]`, затем возвращается перед штатным поворотом стрелками.
Обычный проход через освобождённый блок движения обходит функцию коротким JMP.

Общая физика вызывается и героем, и ИИ. В ранней прямой версии первый
обновлённый объект мог забирать общий угол мыши, из-за чего герой терял поворот.
Это воспроизведено на инструкциях прежней вставки: вызов от ИИ обнулял
накопитель и поворачивал другой объект. Исправленная функция проверяет
адрес возврата штатного вызова героя в `[bp+2]`: `22AAh` RUS / `285Ah` ENG.
Вызов ИИ (`3D93h` RUS / `44FCh` ENG) оставляет угол и накопитель нетронутыми.
Контексты обоих вызовов дополнительно проверяются патчером. Смещение может
быть потреблено только героем, один раз, через `xor ax,ax; xchg ax,[MOUSE_X]`.

Вставки — собственный код WASDify под MIT, NASM `BITS 16`. Размеры блоков:
195, 89, 75, 142, 45 и 3 байта. Новых селекторов и релокаций нет, длина EXE
сохраняется. Два штатных far-pointer fixup сохранены, девять устаревших удалены.
Мышиная вставка использует EAX/ECX/EDX и флаги; стек не меняет. Функция угла
изменяет AX/флаги и воспроизводит исходный контракт ES:BX и near-call/RET.
DS/SS остаются штатным общим сегментом данных. Проверяются контексты,
ожидаемые байты, связи релокаций и отсутствие fixup поверх новых инструкций.

Полные предыдущие сборки распознаются по байтам и релокациям, включая прямую
мышь с 0,4°. Её обновление меняет только мышиный блок. Повторное применение
не пишет файл; смесь оригинальных и патченных участков отклоняется.

```powershell
python scripts/build_kremlin_wasd.py --nasm build/tools/nasm-2.16.03/nasm.exe
$env:PYTHONPATH='src;build/research-deps'
python scripts/analyze_kremlin_wasd.py originals/games/pkr/RUS/PKR.EXE
python scripts/analyze_kremlin_wasd.py originals/games/pkr/ENG/PKE.EXE
python -m unittest discover -v
```

Сборщик выполняет `nasm -f bin -DSECTION=1..6 -DENG=0/1`, требует совпадения
с готовыми байтами `data/kremlin_wasd.json` и печатает SHA-256 каждой вставки.
NASM 2.16.03, Capstone 5.0.9 и Unicorn 2.1.4 нужны только для разработки.
В приложении нет сторонних зависимостей или сборки во время запуска.

Проверки: 72 синтетических теста и по 25057 сценариев исполнения инструкций
каждой версии. Проверяются границы signed word, тысячи событий, дробный
остаток, эквивалентность разбиения событий, точные углы на границах 0/360,
все комбинации WASD/стрейфа/стрелок/Shift и однократное потребление мыши.
Таймер, INT 33h и тяжёлая обработка столкновений контролируются эмуляцией.
Реальные столкновения требуют ручной игровой проверки.

Регрессия проверяет 18000 последовательных кадров с 1–4 обновлениями ИИ перед
обновлением героя, быстрыми сменами знака, нулевыми кадрами и повторным
обновлением героя без нового ввода. Это число кадров соответствует шести
минутам при 50 обновлениях в секунду, но не является игровым прогоном DOSBox.
Накопитель сохраняется до вызова героя; углы других объектов не изменяются.

## Рабочие копии

Применение через общий Service, CLI или GUI доступно штатно:

```powershell
wasdify plan "C:\Games\Kremlin\PKR.EXE" --patch wasd
wasdify apply "C:\Games\Kremlin\PKR.EXE" --patch wasd
```

Для английской версии укажите `PKE.EXE`. В GUI выберите WASD-патч,
проверьте план и примените; бэкап включён по умолчанию.

Прежняя исправленная ×4 сохранена в `mqa/games/pkr/` без изменений.
Прямой поворот с текущими 0,2° — в `mqa/games/pkr-direct/`, с бэкапами.
Русская рабочая копия также содержит исправление разрешения. Эталоны
`originals/` не изменяются. DOSBox монтирует `mqa/games` как `C:`.

```text
cd \pkr-direct\rus
pkr.exe
```

Английская версия: `cd \pkr-direct\eng`, затем `pke.exe`.
Игры, бэкапы и окружение `mqa/` не включаются в Git и пакет.
