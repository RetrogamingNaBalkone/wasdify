# Выбор оружия

Обновление 20 октября 2026 года: первая правка устраняла небезопасное чтение,
но не устраняла падение после нескольких переключений. Дополнительно исправлен
курсор очереди событий. В DOSBox на отдельных копиях RUS/ENG подтверждены
64 последовательных переключения пистолета и ружья для каждого языка.

Исследование 20 октября 2026 года после сообщения о падении при повторном
выборе ружья клавишей 2 в сборке с WASDify. Отдельный патч:
`weapon-selection-fix`. Исходные образцы и SHA-256:

## Подтверждённые факты

Ghidra 12.1.2, x86 16-bit protected NE: все три команды вызывают общий
метод выбора. RUS: NE-сегмент 14, относительный адрес `1FCDh`,
Ghidra `1068:1FCD`, файловое смещение `107CDh`.
ENG: NE-сегмент 5, относительный адрес `257Dh`, файловое смещение `11D7Dh`.
Номера NE-сегментов не являются селекторами DOSBox.

Объект игрока содержит таблицу far-указателей `+AAh`, индекс текущего слота
`+CEh` и индекс ожидаемого выбора `+D0h`. Штатный метод сначала получает
индекс текущего слота, затем **без проверки** разыменовывает соответствующий
указатель и читает поле оружия `+81h`. Оно записывается в `+D0h` перед
проверкой равенства с запрошенным номером. Проверка наличия оружия происходит
позже, поэтому не защищает это чтение.

```asm
mov ax, es:[bx+0CEh] ; индекс уже известен
shl ax, 2
add bx, ax
les bx, es:[bx+0AAh] ; может быть пустой/недействительный указатель
mov ax, es:[bx+081h] ; небезопасное чтение
les bx, [bp+6]
mov es:[bx+0D0h], ax
cmp es:[bx+0D0h], dx ; повторный выбор проверяется только здесь
```

В диагностическом DOSBox на новом уровне без подобранного оружия слоты
нулевые, текущий индекс 0. Нажатие клавиш выбора в исходном обработчике
меняет ожидаемый индекс с 0 на постороннее значение 19. Это наблюдаемое
следствие чтения через пустой указатель; данный запуск сам по себе не
воспроизвёл падение с уже подобранным ружьём.
После исправления тот же сценарий DOSBox сохраняет ожидаемый индекс 0
при двукратных нажатиях каждой из клавиш 1, 2 и 3; игра продолжает работать.

## Исправление

18 байт от `shl ax,2` до повторного `les bx,[bp+6]` заменены на NOP.
В AX остаётся текущий индекс из `+CEh`, а ES:BX продолжает указывать на игрока.
Проверки равенства, наличия запрошенного оружия и состояния анимации остаются
штатными. Соответствие номера оружия индексу слота подтверждается методом
подбора: он использует поле `+81h` как индекс той же таблицы.

Файловые диапазоны: RUS `[107E4h,107F6h)`, ENG `[11D94h,11DA6h)`.
Новых переходов, сегментов, релокаций и ASM-полезной нагрузки нет.
Размер EXE сохраняется. Для этой части патчер проверяет единственный 135-байтовый контекст
в кодовых NE-сегментах, исходное/полностью исправленное состояние 18 байт,
эпилог функции и отсутствие затрагивающих правку цепочек релокаций.
Имена файлов и хэши не заменяют эти проверки.

## Падение при многократном переключении: очередь событий

Скриншот `image0006-rendered.png` показывает исключение 0Dh возле косвенного
far-вызова `call far es:[bx+8]` в обработчике событий. В оригинальном RUS это
NE-сегмент 8, относительное смещение `0332h`, файловое `C532h`.
Номера сегментов и селекторы из окна ошибки нельзя взаимозаменять.

Статический разбор оригинальных инструкций и отдельный запуск DOSBox подтвердили:

1. Обработчик очереди держит текущий объект в глобальном far-указателе
   RUS `DS:03ECh` / ENG `DS:03F4h`, а его массив событий — в отдельном указателе.
2. Завершение скрытия старого оружия вызывает активацию нового. Первое событие
   нового оружия вставляет его объект в кольцевой список сразу после текущего.
3. Вставка также заменяла глобальный текущий указатель новым объектом.
   Продолжающийся обработчик сохранял старый массив, но уже читал и изменял
   счётчики нового объекта. Последующее переключение приводило к выходу за
   границы массива и вызову постороннего адреса.

Правка удаляет только присваивание курсору при вставке в **непустое** кольцо:

```asm
mov es:[bx+8], eax       ; связать текущий объект с новым — сохраняется
mov [03ECh], eax         ; RUS: заменено четырьмя NOP
jmp short inserted
; Ветка первоначального заполнения пустого кольца остаётся исходной.
```

RUS: NE-сегмент 8, относительный диапазон `[0169h,016Dh)`, файловый
`[C369h,C36Dh)`. ENG: NE-сегмент 3, относительный `[151Fh,1523h)`,
файловый `[CD1Fh,CD23h)`. Ожидаемые байты `66 A3 EC 03` / `66 A3 F4 03`;
замена `90 90 90 90`. В обоих вариантах проверяется уникальный 101-байтовый
контекст связей кольца, ветки пустого списка и счётчика, а также все цепочки
релокаций, которые могли бы затронуть правку.

Итого изменяются 22 байта без изменения длины файла и релокаций. Старый вариант
патча с 18 NOP распознаётся и обновляется одной дополнительной правкой;
повторное применение текущего варианта не меняет файл.

## Проверки и ограничения

`scripts/GhidraKremlinWeapons.java` экспортирует выбранные функции через
headless Ghidra; результат хранится в игнорируемом `build/`.
Исходный проект открывается с `-readOnly -noanalysis`.

`scripts/verify_kremlin_weapons.py` читает EXE без записи, строит исправление
в памяти и исполняет инструкции в Unicorn. Для каждого языка 21 сценарий:
пустой и недействительный текущий указатель, повторный выбор всех трёх
слотов, выбор отсутствующего оружия, обычное переключение и активация при
пустом текущем слоте. Небезопасные чтения исходного метода воспроизводятся
ошибкой доступа; исправленный метод их не выполняет. Для корректных
указателей совпадают выбранные ветви и ожидаемый индекс, проверен стек возврата.
Это изолированная проверка обработчика, внешние методы анимации не исполняются.
Дополнительно восемь синтетических сценариев исполняют оригинальные инструкции
вставки события для двух языков до/после исправления, с пустым и непустым
кольцом. Проверяются курсор, обе связи кольца и число активных объектов.

```powershell
$env:PYTHONPATH='src;build/settings-deps'
py scripts/verify_kremlin_weapons.py originals/games/pkr/RUS/PKR.EXE
py scripts/verify_kremlin_weapons.py originals/games/pkr/ENG/PKE.EXE
```

Unicorn нужен только для исследования. Unit-тесты используют синтетические
NE-данные и проверяют сигнатуры, повреждения, неоднозначность, релокации,
Service, бэкап и повторное применение. Общий план всех семи патчей проверен
на обоих оригиналах и ранее исправленной рабочей копии с INI.
Полный `py -m unittest discover -v`: 114 тестов, без ошибок и пропусков.
Wheel собран, установлен в отдельный каталог; из `C:\Windows` проверены
импорт установленного пакета, семь патчей и оба языковых каталога.

Патч применён через Service к рабочему `mqa/games/pkr/PKR.EXE`, бэкап:
`PKR.EXE.wasdify-fb45790178d3461f8cb8fe0673227b27.bak`.
SHA-256 до: `e18ce447dc5db6cf6369ccc2dc677a2e3696e6b3f3556f270e741653f87d5a5d`;
после: `daa4d1bf44f1e484bacda0c616a81a302acd1cb1bbae9154dd23ab192374a43c`.
Повторный анализ всех семи патчей готов и не содержит правок.

Эти SHA-256 и резервная копия относятся к первому варианту исправления.
После повторного сообщения пользователя падение воспроизведено в новой
диагностической RUS-копии со всеми семью патчами: подбор обоих видов оружия,
переход на пистолет и обратно на ружьё. Предыдущий вариант завершил игру
при втором переключении. После сохранения курсора по 64 переключения RUS
и ENG завершились успешно, с проверкой текущего и ожидаемого слота.
Отдельный запуск RUS в 640×400 также выдержал 64 переключения. Сценарий
дожидается окончания подъёма оружия перед следующим обычным переключением;
запрос во время подъёма штатная игра может проигнорировать.
ENG дополнительно выдержала 64 запроса с паузой 0,2 секунды, включая запросы
во время анимации; наблюдались оба выбранных слота и незавершённые переходы.

В диагностических запусках игрок перемещается на существующие клетки подбора
через гостевую память. Подбор, создание оружия, анимации и очередь событий
исполняются самой игрой; файлы оригиналов не меняются. Проверены новые уровни,
DOSBox `core=normal`, Pentium, 60000 циклов, режимы 320×200 и RUS 640×400. Это не проверка
всех уровней, сохранений и вариантов эмуляции.

Воспроизводимый сценарий: `scripts/verify_kremlin_weapon_switching.py`.
Все рабочие копии, отчёт JSON и экран ошибки при отказе остаются в `mqa/`.
Опция `--previous` отменяет только новую четырёхбайтовую правку в отдельной
диагностической копии для контрольного воспроизведения старого падения.

```powershell
$env:PYTHONPATH='src;scripts'
py scripts/verify_kremlin_weapon_switching.py ru
py scripts/verify_kremlin_weapon_switching.py en
py scripts/verify_kremlin_weapon_switching.py ru --mode 1
py scripts/verify_kremlin_weapon_switching.py en --delay .2
py scripts/verify_kremlin_weapon_switching.py ru --previous --delay .2
```

Контроль с `--previous` зависит от взаимного времени событий: падение не
гарантировано при каждой последовательности. Отдельные серии старого варианта
также проходили без исключения; это не опровергает воспроизведённый выше сбой
и изменение курсора, подтверждённое исполнением инструкций в Unicorn.

Рабочий `mqa/games/pkr/PKR.EXE` обновлён через Service с предыдущего варианта;
резервная копия: `PKR.EXE.wasdify-8d7a41ee927f45ba8ae562d5e3047a4a.bak`.
SHA-256 после обновления:
`a2bfdf26c2b2618769e40f2eb976874e4a3f2e2a46737c5d7ab7498eaa05e30b`.
Повторный анализ всех семи патчей готов и не содержит правок.

Применение к рабочей копии при закрытой игре:

```powershell
wasdify apply mqa/games/pkr/PKR.EXE --patch weapon-selection-fix
```

Бэкап включён по умолчанию. Оригиналы не изменяются.
